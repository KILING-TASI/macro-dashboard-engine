## 一、目标与定位

### 1.1 核心目标

抓取国内外重要宏观数据，通过图表可视化，完成**宏观周期研判**，并分析**对股票市场的传导影响**，输出一份开箱即用的单文件 HTML 看板。

### 1.2 解决的问题

传统宏观分析工具的三个痛点：

1. **数据分散**：国内指标在统计局/东财，海外在 FRED，需要人工搬运
2. **缺乏体系**：单看指标涨跌，没有周期框架串联，难以形成判断
3. **传导断层**：知道"CPI 涨了"，但不知道"该配什么行业"

本 Skill 用「**周期梯队框架**」把散落的数据串成一条从宏观到配置的完整链条。

### 1.3 设计原则

| 原则 | 说明 |
|---|---|
| **能算的算，算不了的明说** | 数据驱动的周期（朱格拉/库兹涅茨）老实做回归；无法量化的（康波）用定性框架并**强制标注**，绝不硬造数据结论 |
| **永远能出图** | 三级兜底（实时→自定义→离线快照），任一数据源挂掉都不影响出板 |
| **单文件交付** | 内联 ECharts，双击即可看，无需服务器、无需联网 |
| **红涨绿跌** | 遵循中国股市颜色惯例 |

## 三、周期梯队框架（核心方法论）

看板的骨架是「**短—中—长**」三层周期梯队，对应不同的时间尺度与决策用途：

| 层级 | 周期 | 尺度 | 主导变量 | 决策用途 |
|---|---|---|---|---|
| **战术层** | 美林时钟、库存、信用、流动性、估值、铜金比、中美利差、盈利、情绪、地产 | 3月~4年 | 增长/通胀/信用/流动性 | 未来 1-2 季度仓位与行业轮动 |
| **战略层** | 朱格拉、库兹涅茨、债务周期 | 7~25年 | 设备投资/地产/债务 | 中期产业配置偏向 |
| **背景层** | 康波、熊彼特（定性） | 50~60年 | 技术革命集群 | 大类资产长期β与主题方向 |

**共振逻辑**：当短周期（库存）与中周期（朱格拉）共振向上时配置胜率最高；当长周期（康波）处于萧条期时，需对中期乐观信号保持警惕。

## 四、数据层设计

### 4.1 数据源与实测结论

| 数据源 | 用途 | 指标数 | 实测状态 |
|---|---|---|---|
| **东方财富** `datacenter-web.eastmoney.com` | 国内宏观 | 9 | ✅ 可用，需 `Referer: https://data.eastmoney.com/` |
| **FRED** `fred.stlouisfed.org` | 海外 + 长周期 | 29 | ✅ 可用，**不能带自定义 User-Agent** |
| **新浪财经** `money.finance.sina.com.cn` | 行业指数行情 | 9 | ✅ 可用 |
| 东财 push2 行情 | 行业行情（备选） | — | ❌ 被拦截（RemoteDisconnected） |
| 腾讯 ifzq | 行业行情（备选） | — | ❌ 被拦截（HTTP 501） |

### 4.2 关键约束（踩坑记录）

1. **FRED 的 User-Agent 陷阱**：FRED 对携带自定义 UA 的请求会直接拒绝/超时。脚本内 `HEADERS = {}`，**勿改动**。
2. **长序列取样条数**：日频序列默认只取 260 条（约 1 年）。做量化归因时，汇率/美债因子需要更长历史，已调整为 **1300 条（约 64 个月）**，否则与行业收益率的月份交集不足。
3. **新浪行情代码陷阱**：部分中证行业代码（材料/工业/电信/公用/银行/地产/证券）在新浪返回**陈旧数据**（如 2013-2016），必须实测后剔除，否则污染回归结果。

### 4.3 指标清单

**国内（东财，9 项）**

| key | 指标 | 说明 |
|---|---|---|
| `gdp` | GDP 同比 | 季度 |
| `cpi` | CPI 同比 | 月度 |
| `ppi` | PPI 同比 | 月度 |
| `pmi` | 制造业 PMI | 月度 |
| `retail` | 社零总额 | 月度 |
| `m0` / `m1` / `m2` | 货币供应 | 月度，含同比 |
| `house` | 70 城房价指数 | 月度（新房/二手） |

**海外（FRED）**

- 基础 7 项：`us_cpi`、`us_unrate`、`fedfunds`、`us10y`、`usdcny`、`usd_index`、`wti`
- P1 扩展 6 项：`cn_rate`、`copper`、`gold`、`us10y_real`、`vix`、`us_curve`
- P2 扩展 3 项：`us_indpro`、`us_retail`、`us_payems`
- 派生 2 项：`copper_gold`（铜金比）、`cn_us_spread`（中美利差）
- **P3 长周期 11 项**：`lj_equip`、`lj_gfcf`、`lj_gdp`、`lj_house`、`lj_houst`、`lj_cs`、`lj_mortg`、`lj_debtgdp`、`lj_credit`、`lj_lev`、`lj_rec`（最早回溯至 1919 年）

## 五、计算层设计

### 5.1 短周期引擎（compute_cycle.py）

**10 个周期**：美林时钟、库存周期、信用周期、货币流动性、估值（ERP）、铜金比、中美利差、盈利、情绪、地产。

**关键方法**：

- **增长/通胀评分**：多维度加权，返回 `(score, evidence[], n_dims)`。当某维度无数据时 `n_dims` 减少，避免"缺数据被误判为周期信号"。
- **水平+方向融合** `_level_and_dir`：
  ```
  score = 0.6 × tanh(level/scale) + 0.6 × tanh(direction/scale)
  ```
  解决"PMI 低位改善被误判为衰退"的问题（只看绝对水平 <50 会误判）。
- **异常值清洗** `_clean_outliers`：迭代剔除 + 邻值还原，只去真尖刺（如 M1-M2 剪刀差 +2.2 的源数据异常）。
- **象限判定**：`classify_quadrant` 在任一维度无数据时返回「数据不足」，不硬判。

### 5.2 长周期引擎（compute_long_cycle.py）

**计算流程**：

```
原始序列(季/月/周)
  → 统一重采样为季度（每季取最后有效值）
  → z-score 标准化
  → 去超长趋势（减去 2×长窗移动平均）
  → 带通滤波：band(t) = MA(short)(x) − MA(long)(x)
  → 再标准化 + ±3σ 截断
  → 水平(z) + 方向(4期斜率) 融合 → 阶段判定
  → 局部极值识别 → 历史峰谷（含最小跨度约束滤噪）
```

**三个周期的参数**：

| 周期 | 合成输入 | 带通窗口 | 理论周期 |
|---|---|---|---|
| 朱格拉 | 设备投资同比 + 私人固投同比 | `MA(20Q) − MA(48Q)` | 7-11 年 |
| 库兹涅茨 | 住宅投资同比 + 新屋开工 + 房价同比 | `MA(40Q) − MA(100Q)` | 15-25 年 |
| 债务 | 债务/GDP **同比变化** + 银行信贷脉冲 | 直接 z-score | 长债代理 |

> **关键设计**：债务周期必须用**变化率**而非水平值。债务/GDP 长期单调上升，用水平值做 z-score 会永远输出"高位"，毫无判别力。

**历史验证结果**：

- **朱格拉**：谷底 1989Q2（储贷危机）、2001Q1（互联网泡沫）、2007Q4（次贷危机）—— 与真实设备投资周期高度吻合；峰间平均跨度约 8 年，落在理论区间内
- **库兹涅茨**：谷底 1990Q2（储贷地产危机）、2011Q3（次贷后地产出清）、2024Q3

### 5.3 量化归因引擎（regress_attribution.py）

**目的**：用历史回归得到的**真实 beta**，替代原本基于经验判断的「因子×行业敏感度矩阵」。

**方法**：

1. 行业指数月度**超额收益**（减沪深300）
2. 对 6 个宏观因子月度变化做 **OLS 多元回归**（含截距）
3. 输出标准化 beta 矩阵 + t 值近似 + R²

**6 个宏观因子**：增长(PMI 变化)、通胀(CPI 同比变化)、流动性(M1 同比变化)、汇率(USDCNY 变化)、海外利率(10Y 美债变化)、周期品(铜金比变化)

**实现细节**：

- 纯 Python OLS（正态方程 + 高斯消元），**不依赖 numpy**
- t 值近似：`se(b) = sqrt(σ² × (X'X)⁻¹ᵢᵢ)`
- 样本不足（n ≤ 参数个数）时返回空，不硬算

**实测结果（33 个月样本，5 行业）**：

| 行业 | 增长 | 通胀 | 流动性 | 汇率 | 美债利率 | 铜金比 | R² |
|---|---|---|---|---|---|---|---|
| 能源 | -3.44 | -1.29 | +0.81 | **-17.53** | +7.93 | -0.09 | 0.18 |
| 主要消费 | -1.65 | -2.50 | -0.54 | -8.38 | +4.15 | -0.17 | 0.10 |
| 医药卫生 | -1.37 | -2.13 | -0.72 | -11.53 | +4.35 | -0.16 | 0.12 |
| 金融 | -1.61 | -1.41 | +0.21 | **+0.78** | +3.94 | -0.01 | 0.12 |
| 信息技术 | **+1.53** | +1.56 | -0.73 | +16.04 | **-7.76** | +0.27 | 0.08 |

**结果解读（符合经济直觉）**：

- 信息技术是**唯一对增长正敏感**的行业（成长股属性），且对美债利率最敏感（久期最长）
- 能源在人民币贬值时大跌（美元计价商品），美债利率上行反而利好（通胀逻辑）
- 金融对汇率近乎中性、其他因子敏感度都低（防御属性）
- **R² 0.08~0.18 如实标注** —— 月度宏观数据噪声大，解释力有限属正常，不做美化

### 5.4 定性框架（康波 / 熊彼特）

**为什么不做数据驱动**：

- 康波描述技术革命集群的扩散与出清（50-60 年），全球无被广泛认可的量化序列
- 即使 1919 年起的美国工业生产指数，100 年历史仅覆盖约 1.7 轮，样本不足以统计识别
- 硬算出来的"康波"不可复现、不可验证

**采用方案**：内置六次技术革命浪潮时间轴 + 结构特征匹配，看板中**强制标注「定性判断，非数据计算」**，与数据驱动结论严格区分显示。

| 浪次 | 名称 | 核心技术 | 时间 | 主导国 |
|---|---|---|---|---|
| 1 | 纺织与蒸汽 | 蒸汽机、纺织机械、铁 | 1780-1840 | 英国 |
| 2 | 钢铁与铁路 | 钢铁、铁路、轮船 | 1840-1890 | 英/德 |
| 3 | 电气与重化工 | 电力、内燃机、化工 | 1890-1950 | 德/美 |
| 4 | 汽车与石化 | 汽车、石化、电子 | 1950-1990 | 美/日 |
| 5 | 信息技术 | 计算机、互联网、移动通信 | 1990-2020 | 美/中 |
| 6 | AI 与新能源 | AI、光伏储能、生物、量子 | 2020-2060 | 美/中 |

**当前定位**：第五浪下半程 → 衰退/萧条过渡；第六浪孕育中。

## 七、工作流

### 7.1 一键生成（推荐）

首次试用可离线生成教学报告，每次在指定目录下另建运行目录，保留旧结果：

```powershell
python scripts/run_pipeline.py --demo --workdir local-data/demo
```

成功提示会给出HTML路径。正式取数改用 `python scripts/run_pipeline.py --workdir local-data/research`，需要网络及相应来源权限；接口失败和缺项不能用教学数据补齐。流水线整理来源数据、计算周期与行业历史关联并生成看板，历史关联不等于因果归因。

### 7.2 分步执行（调试用）

以下示例使用一致的输入文件名。请先进入自己新建的研究目录，把命令中的脚本路径改为完整源码下对应路径，或在源码根目录运行并确认这些输出文件尚不存在。分步脚本的覆盖行为不同于流水线，重复研究建议使用上面的 `--workdir` 入口。

```powershell
python scripts/fetch_eastmoney.py --out eastmoney_data.json
python scripts/fetch_fred.py --out fred_data.json
python scripts/fetch_industry.py --months 36 --out industry_data.json
python scripts/compute_cycle.py --eastmoney eastmoney_data.json --fred fred_data.json --out cycle.json
python scripts/compute_long_cycle.py --fred fred_data.json --out long_cycle.json
python scripts/regress_attribution.py --industry industry_data.json --eastmoney eastmoney_data.json --fred fred_data.json --out attribution.json
python scripts/build_dashboard.py --eastmoney eastmoney_data.json --fred fred_data.json --cycle cycle.json --longcycle long_cycle.json --attribution attribution.json --out macro-dashboard.html
```

Windows使用 `python`（或已安装的 `py -3`）；Linux/macOS按本机解释器配置可改用 `python3`。已安装CLI的用户优先使用首页中的虚拟环境入口。

### 7.3 自定义数据接入

用户有自有数据时，构造与 `fetch_eastmoney.py` 输出同构的 JSON 即可：

```json
{"source": "user", "as_of": "2026-08",
 "indicators": {"cpi": {"name":"CPI同比","unit":"%","dates":["2026-07","2026-08"],
                         "series":{"value":[0.5,0.8]},"latest":0.8,"prev":0.5}}}
```

## 十、风险与边界

> **本设计方案的输出仅为研究框架，不构成投资建议。**

- 宏观数据存在披露滞后、历史修订、口径变化
- 周期划分与资产关联属于经验性研究框架，**不是确定性预测**
- 相关关系不等于因果关系
- 量化归因基于历史回归，样本期有限（33 个月），R² 偏低，beta 不稳定，不代表未来
- 看板日期不保证等于数据最新日期
- 康波/熊彼特为定性判断，已被明确标注

## 十一、技术栈

| 组件 | 选型 | 说明 |
|---|---|---|
| 语言 | Python 3.11 | 无第三方依赖（零依赖设计） |
